## Purpose
This file converts Fisher Prize rules, official judging criteria, and publicly traceable past-winner patterns into tactical matrices for maximizing competitiveness. It is not a topic-selection memo and does not create the actual Fisher poster or StoryMap.

## Source Rules

### Source hierarchy
1. **User-provided Fisher instructions** are the baseline for current submission rules and judging criteria.
2. **Official Harvard/CGA pages** are preferred for current rules and recent winner records.
3. **Harvard Gazette / Harvard departmental pages** are treated as official Harvard public records for historical winners.
4. **Winner CVs, profiles, public project pages, or external publication pages** are used only when official winner pages are absent or incomplete.
5. **Prior-summary only** rows are retained only when no stronger public source was found; they must stay labeled and should not be treated as settled fact.

### Confidence labels
Use exactly one of these labels per row:

| Confidence | Meaning | How to use tactically |
|---|---|---|
| `Official` | Supported by Harvard/CGA, Harvard Gazette, Harvard departmental page, or Harvard prize-list source. | Safe to use as a pattern example. |
| `Public secondary` | Supported by non-Harvard public article/project page or accessible public publication page. | Use cautiously; good for method/topic pattern, not definitive award administration. |

## Current Fisher Rules and Criteria

### Eligibility and award
- The Fisher Prize for excellence in GIS is awarded to one Harvard graduate student and one Harvard undergraduate student enrolled in the academic year and in good standing.
- Group projects are allowed and should be submitted as one entry.
- The current prize is a $500 cash award for each top undergraduate and graduate entry.

### Deadline and submission process
- Deadline: **Sunday, May 3, 2026 at 11:59 p.m.**
- Registration: register through the Fisher Prize page using HarvardKey.
- After registration confirmation, submit the poster PDF or StoryMap URL by email to Jeff Blossom at `jblossom@cga.harvard.edu` before the deadline.

### Format constraints
- Poster route: **42” x 36”**, **PDF format**, **no more than 350 words of descriptive text**. Map legends, labels, title, citations, and captions do not count toward the 350-word descriptive-text cap.
- StoryMap route: a Story Map website showcasing the work.

### Five official judging criteria
1. Innovation and creativity of chosen topic
2. Use of GIS in performing the project
3. Data — complexity, relevance to topic, properly documented
4. Analytical approach and execution
5. Visualization / cartographic communication effectiveness

## Repeatable Winner Patterns

1. **Spatial necessity is visible.** Winning projects usually answer a question that is hard to answer without GIS: where destruction occurred, who has access, how hazards overlap vulnerability, how territory changes, or how networks constrain movement.
2. **The topic has external stakes.** Conflict, climate risk, public health, conservation, urban inequality, archaeological reconstruction, and energy use recur because they matter beyond a class assignment.
3. **The data stack is layered.** Winners often combine multiple data types: imagery + classification, hazard + demographics, chemistry + sites, conflict + socioeconomic variables, terrain + field recordings.
4. **The method does more than plot.** Common high-scoring moves include change detection, accessibility/network analysis, suitability/risk modeling, classification, multi-scale integration, location-allocation, and spatiotemporal analysis.
5. **Visualization is argumentative.** The map is not decoration; it is the evidence. Strong entries make a pattern immediately legible while preserving enough methodological credibility.
6. **Time strengthens the story.** Many winners use before/after, historical reconstruction, spatiotemporal trends, or future-risk scenarios.
7. **Design-grade cartography can compensate for complexity only if data and method remain documented.** Design-heavy winners still need data provenance and analytical transparency.

## Poster vs StoryMap Strategy Matrix

| Dimension | Poster route | StoryMap route | Winning implication |
|---|---|---|---|
| Compliance | Must be 42” x 36”, PDF, and <=350 words of descriptive text excluding legends/labels/title/citations/captions. | Must be a Story Map website showcasing the work. | Poster has sharper rejection risks; StoryMap has scope-creep risk. |
| Best use case | One strong claim, one hero map, 2–4 supporting maps, compact workflow. | Sequential argument, temporal change, interactive layers, narrative exploration. | Choose poster for focused evidence; StoryMap for process/time/geographic exploration. |
| Visual storytelling | Fast judge scan; every inch matters. | Scroll-based progression can teach the reader. | Poster must win in 30 seconds; StoryMap can win through guided discovery. |
| Analytical depth | Must compress methods into diagram/captions; tables must be minimal. | Can show method, data, results, and limitations in richer sections. | Poster needs ruthless prioritization; StoryMap needs navigation discipline. |
| Risk | Wrong size, non-PDF, word count, clutter, tiny maps. | Broken links, slow load, excessive narrative, weak map hierarchy. | Run format QA early. |
| Data/source documentation | Source footnotes/citations can be compact; data table may be in small panel. | More space for source/provenance sections. | In both routes, documented data is a judging criterion, not optional. |
| Cartographic effectiveness | Hero map + small multiples. | Interactive or progressive maps. | Use the medium to make the spatial insight unavoidable. |
| Recommended strategy | Best when the project has a clean spatial thesis and polished visual hierarchy. | Best when the project has temporal/process complexity or benefits from interactive exploration. | Select format based on argument structure, not personal preference. |

## Upgrade-Move Index

| Weakness observed | Upgrade move | Fisher criterion improved |
|---|---|---|
| “I have maps but no analysis.” | Add a spatial operation that changes the conclusion: classify, model, allocate, measure access, detect change, or test clusters. | Use of GIS; analytical execution |
| “My topic is interesting but not spatially necessary.” | Rewrite the research question around where, why there, who is exposed, what changed, or how access/control differs by place. | Innovation; use of GIS |
| “My data is messy.” | Create a source/provenance table, document preprocessing, align CRS/time/resolution, and disclose uncertainty. | Data |
| “My method is complex but opaque.” | Add workflow diagram, parameter table, validation check, and one example of an error/limitation. | Analytical execution |
| “My poster is text-heavy.” | Move descriptive prose into captions/labels, use a claim-title, and cut to 350-word audit. | Visualization; compliance |
| “My project looks like a class assignment.” | Add a judge-visible payoff: policy implication, historical recovery, risk prioritization, design intervention, or theoretical reframing. | Innovation; visualization |
| “My visual is attractive but not rigorous.” | Add scale bars, sources, uncertainty, method note, and data lineage. | Data; analytical execution |
